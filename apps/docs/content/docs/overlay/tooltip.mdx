The **Tooltip** shows a short label on hover or focus, built on Radix —
keyboard-accessible, screen-reader friendly, portaled, and theme-aware.
Zero-config: wrap a trigger and pass `content`. Wrap the app in `TooltipProvider`
only if you want a shared open delay. In Angular it's the `[bpdmTooltip]` directive.

## Sides

The `side` prop (`top` — default — `right`, `bottom`, `left`) sets where it
appears; it's collision-aware and flips to stay in view.

<Preview>
  <TooltipSidesDemo />
</Preview>

```tsx title="tooltip-sides.tsx"
import { Tooltip } from '@bpdm/ui/tooltip';
import { Button } from '@bpdm/ui/button';

export function Sides() {
  return (

      <Tooltip side="bottom" content="On the bottom"><Button>Bottom</Button></Tooltip>
```

## Rich content

`content` accepts any node — a heading, shortcut hint, or small block — not just
a string.

<Preview>
  <TooltipRichDemo />
</Preview>

<Tabs groupId="framework" items={['React', 'Angular']}>
  <Tab value="React">

```tsx title="tooltip-rich.tsx"
import { Tooltip } from '@bpdm/ui/tooltip';
import { Button } from '@bpdm/ui/button';

export function RichTooltip() {
  return (
    <Tooltip
      content={
        <div className="space-y-1">
          <p className="font-medium">Keyboard shortcut</p>
          <p className="text-muted-foreground">Press ⌘K to open search.</p>
        </div>
      }
    >
      <Button variant="secondary" appearance="outline">Rich content</Button>
    </Tooltip>
  );
}
```

  </Tab>
  <Tab value="Angular">

```ts title="rich-tooltip.ts"
  imports: [BpdmTooltip, BpdmButton],
```

## On a disabled trigger

A disabled control emits no hover/focus events, so a tooltip can't open on it
directly. bpdm handles this — pass a `disabled` child and it's wrapped in a
focusable element, so the "why is this disabled?" tooltip still works and stays
keyboard-reachable.

<Preview>
  <TooltipDisabledTriggerDemo />
</Preview>

<Tabs groupId="framework" items={['React', 'Angular']}>
  <Tab value="React">

```tsx title="tooltip-disabled-trigger.tsx"
import { Tooltip } from '@bpdm/ui/tooltip';
import { Button } from '@bpdm/ui/button';

export function PublishButton() {
  return (
    <Tooltip content="You need the Admin role to publish">
      <Button disabled>Publish</Button>
    </Tooltip>
  );
}
```

```html title="publish.html"
</span>
```

## API

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `content` | `ReactNode` | — | What the tooltip shows. Empty/nullish → no tooltip. Angular: `[bpdmTooltip]` (string or `TemplateRef`). |
| `side` | `top \| right \| bottom \| left` | `top` | Edge it appears on. Angular: `bpdmTooltipSide`. |
| `align` | `start \| center \| end` | `center` | Alignment along the side. Angular: `bpdmTooltipAlign`. |
| `delayDuration` | `number` | `200` | Delay before opening, in ms. |
| `sideOffset` | `number` | `6` | Gap from the trigger, in px. |
| `hideArrow` | `boolean` | `false` | Hide the little arrow. |
| `disabled` | `boolean` | `false` | Turn the tooltip off (the trigger stays fully interactive). |
| `open` / `defaultOpen` | `boolean` | — | Controlled / uncontrolled open. |

Wrap the app in **`TooltipProvider`** (React) only to share one `delayDuration`
across tooltips — a standalone `Tooltip` works without it.

## Accessibility

- Built on Radix Tooltip — opens on **hover and keyboard focus**, closes on
  blur / `Esc`, and is announced to screen readers.
- It's for supplementary hints, not essential info or interactive content — for
  that use a [Popover](/docs/overlay/popover).
- On an icon-only trigger, still give the control its own `aria-label` (the
  tooltip names it visually; the label names it for assistive tech).
- For a disabled control, the trigger is wrapped in a focusable element so the
  explanation remains reachable by keyboard.
