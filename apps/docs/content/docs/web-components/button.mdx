`<bpdm-button>` is the bpdm/ui Button delivered as a framework-agnostic **Web
Component**. It renders a real `<button>` inside its shadow root (so focus and
keyboard behaviour stay native), is themed by the `@bpdm/tokens` CSS variables,
and is **form-associated**: `type="submit"` / `type="reset"` drive the
surrounding native `<form>` exactly like a built-in button, with no extra JS.

## Setup

Register the element once, and load the tokens so it picks up a theme. After that
you just write the tag, in a template, a component, or straight HTML.

The `appearance` attribute sets the style: `solid` (default, filled), `outline`
(bordered, transparent fill), and `ghost` (no border or fill). It composes with
every `variant`.

## Loading

Add the `loading` attribute to show a spinner, mark the element `aria-busy`, and
block activation while a request is in flight. Toggle it from your own code.

<Preview>
  <WcButtonLoadingDemo />
</Preview>

```html title="loading.html"
<bpdm-button id="save" type="submit">Save changes</bpdm-button>

<script type="module">
  const btn = document.getElementById('save');
  btn.closest('form')?.addEventListener('submit', async (e) => {
    e.preventDefault();
    btn.loading = true;
    await fetch('/save', { method: 'POST' });
    btn.loading = false;
  });
</script>
```

## Native form submit

This is the headline feature: `<bpdm-button>` is a **form-associated custom
element**, so `type="submit"` and `type="reset"` work inside a real `<form>`,
the browser (and your server, Rails, Laravel or LiveView) sees an ordinary
submit. No click handlers, no JS glue.

## Theming

The element reads the `@bpdm/tokens` CSS custom properties, which cross the shadow
boundary. Switch themes by setting `data-theme` on an ancestor, or override single
tokens in your own CSS:

```css title="theme.css"
/* one of the four built-in themes */
:root { /* paper (default) */ }
[data-theme='charcoal'] { /* dark */ }

/* or nudge a token, applies to every bpdm element inside */
.brand-area {
  --bpdm-primary: #0ea5e9;
  --bpdm-primary-foreground: #ffffff;
  --bpdm-radius: 0.75rem;
}
```

## API

### Attributes & properties

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `variant` | `primary \| secondary \| success \| info \| warning \| help \| destructive \| contrast` | `primary` | Semantic colour. |
| `appearance` | `solid \| outline \| ghost` | `solid` | Filled, bordered, or text-only. |
| `size` | `sm \| md \| lg \| iconSm \| icon \| iconLg \| none` | `md` | Text sizes, square icon sizes, or `none`. |
| `shape` | `default \| round` | `default` | Token radius, or `round` (pill / circle). |
| `type` | `button \| submit \| reset` | `button` | Native button behaviour inside a `<form>`. |
| `disabled` | `boolean` | `false` | Removes interaction and dims the element. |
| `loading` | `boolean` | `false` | Spinner + `aria-busy`; blocks activation. |
| `loading-label` | `string` | `Loading` | Screen-reader text while loading (property: `loadingLabel`). |

### Slots

| Slot | Description |
| --- | --- |
| *(default)* | The button label. |
| `start` | Leading adornment (e.g. an icon), before the label. |
| `end` | Trailing adornment, after the label. |

### Parts

| Part | Description |
| --- | --- |
| `base` | The inner `<button>`, styled with `::part(base)`. |
| `spinner` | The loading spinner. |

### Events

Standard DOM events bubble from the element, listen for `click` as usual. When
`disabled` or `loading`, activation is swallowed so no `click` escapes.

## Accessibility

- Renders a **native `<button>`** in the shadow root with `delegatesFocus`, so
  <kbd>Tab</kbd>, <kbd>Enter</kbd> / <kbd>Space</kbd>, and the focus ring are the
  platform's own.
- **Icon-only** buttons have no text, so set an `aria-label` describing the action.
- `loading` sets `aria-busy="true"` and keeps the label for context; `disabled`
  exposes `aria-disabled` and drops the element from the tab order.
- Motion honours `prefers-reduced-motion` (the press spring and spinner calm down).
- Logical CSS throughout, so an icon + label pair mirrors under `dir="rtl"`.

## Framework interop

### TypeScript

Declare the tag once so JSX / templates type-check:

```ts title="bpdm-wc.d.ts"
import type { BpdmButton } from '@bpdm/wc/button';

declare global {
  interface HTMLElementTagNameMap {
    'bpdm-button': BpdmButton;
  }
}
```

### Angular

Add `CUSTOM_ELEMENTS_SCHEMA` to any component (or module) that uses the tag.

### Vue

Tell the compiler it's a custom element so Vue doesn't try to resolve it as a Vue
component:

```ts title="vite.config.ts"
export default {
  plugins: [vue({ template: { compilerOptions: { isCustomElement: (tag) => tag.startsWith('bpdm-') } } })],
};
```
