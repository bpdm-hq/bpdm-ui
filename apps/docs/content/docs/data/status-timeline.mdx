The **Status Timeline** shows a lifecycle top-to-bottom — a deployment, an approval,
an onboarding flow. Each step carries a `status` (**complete** ✓, **current** —
pulsing, **pending** — hollow, **failed** ✗), with an optional `timestamp` and
`description`. It's data-driven: pass an `items` array.

## Usage

Pass `items` — each with a `title` and a `status`. Add a `timestamp` (shown on the
right) and a `description` where useful.

## Statuses

The four `status` values — **complete**, **current**, **pending**, **failed** —
each get a distinct marker. The `current` marker pulses; `failed` is destructive-red.

## API

### `StatusTimeline` / `<bpdm-status-timeline>`

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `items` | `TimelineItem[]` | — | **Required.** The ordered steps. |
| `className` | `string` (Angular `class`) | — | Extra classes on the timeline. |

### `TimelineItem`

| Field | Type | Description |
| --- | --- | --- |
| `title` | `string` | The step label. |
| `status` | `complete \| current \| pending \| failed` | The step's state (drives the marker + colour). |
| `timestamp` | `string` | Short meta shown on the right, e.g. `"09:47"`. |
| `description` | `ReactNode` (Angular `string`) | Optional detail under the title. |

## Accessibility

- Renders an ordered list (`<ol>` / `<li>`) — steps are announced in sequence.
- Status is **never colour-only**: each state has a distinct marker/icon
  (✓ complete, a filled pulsing dot for current, a hollow ring for pending, ✗ failed)
  and the `title` describes the step.
- The `current` step's pulse respects reduced-motion preferences.
- `timestamp` and `description` are plain text, read alongside the step title.
