This applies to **every bpdm/ui component**. How you target one in a test depends
on the kind of component:

- **Simple components** (Button, Input, Badge, Switch, …) wrap a single native
  element and forward extra attributes — so a `data-testid` lands directly on it.
- **Composed components** (Select, Multi-select, Tree Select, Dialog, …) render a
  small tree and don't yet forward arbitrary attributes onto their root — target
  them by **role**, **text**, or a **wrapper** you control.

## Simple components — `data-testid`

These forward `data-testid` (and `id`, `aria-*`, any `data-*`) straight to the
element.

<Tabs groupId="framework" items={['React', 'Angular']}>
  <Tab value="React">

```tsx title="form.tsx"
import { Button } from '@bpdm/ui/button';
import { Input } from '@bpdm/ui/input';

<Input data-testid="email" placeholder="you@company.com" />
<Button data-testid="save">Save</Button>
```

```tsx title="form.test.tsx"
import { render, screen } from '@testing-library/react';

screen.getByTestId('email');
screen.getByTestId('save');
```

  </Tab>
  <Tab value="Angular">

`bpdmButton` / `bpdmInput` are directives on native elements, so put the
attribute straight on the element.

```html title="form.html"
<input bpdmInput data-testid="email" placeholder="you@company.com" />
<button bpdmButton data-testid="save">Save</button>
```

```ts title="form.spec.ts"
import { By } from '@angular/platform-browser';

fixture.debugElement.query(By.css('[data-testid="email"]'));
fixture.debugElement.query(By.css('[data-testid="save"]'));
```

  </Tab>
</Tabs>

## Composed components — role, text, or a wrapper

Components like Select don't forward arbitrary attributes onto their root yet.
Prefer **accessible queries** (role/text), or wrap the component in an element
you own.

<Tabs groupId="framework" items={['React', 'Angular']}>
  <Tab value="React">

```tsx title="status.test.tsx"
import { render, screen } from '@testing-library/react';

// 1) Accessible query (recommended) — the trigger is a combobox
screen.getByRole('combobox', { name: /status/i });

// 2) Or wrap it with your own test id
// <div data-testid="status"><Select … /></div>
screen.getByTestId('status');
```

  </Tab>
  <Tab value="Angular">

```ts title="status.spec.ts"
import { By } from '@angular/platform-browser';

// query the host element by tag, or a wrapper you control
fixture.debugElement.query(By.css('bpdm-select'));
fixture.debugElement.query(By.css('[data-testid="status"]'));
```

  </Tab>
</Tabs>

## Other attributes

The same forwarding (`id`, `aria-*`, `data-*`) works on simple components — handy
for label relationships, analytics hooks, or query selectors.

```tsx
<Button id="checkout" aria-describedby="checkout-hint" data-analytics="cta-primary">
  Checkout
</Button>
```

<Callout type="info">
  Querying by **role** and **text** (Testing Library's recommendation) is the most
  robust approach — it works across every component and doubles as an
  accessibility check.
</Callout>
